เหนื่อยกับการอธิบายใหม่ทุกแชต Claude เลยสร้างสมองของ AI ไว้บน GitHub

อ่านในภาษาอื่น: English · Bahasa Indonesia · हिन्दी · العربية

ซีรีส์ · สร้างออร์เคสเตรชัน AI
  1. ตอนที่ 1เหนื่อยกับการอธิบายใหม่ทุกแชต Claude เลยสร้างสมองของ AI ไว้บน GitHub

เพื่อให้ได้ผลลัพธ์เดียวกันไม่ว่าจะสั่งงานจากอุปกรณ์หรือหน้าต่างแชตไหน ผมสร้างสมองของ AI ไว้ในรีโพซิทอรี GitHub นอก Claude

ยิ่งใช้ Claude มากเท่าไร ผมก็ยิ่งสั่งงานจากคอมที่บ้านบ้าง จากโน้ตบุ๊กบ้าง จากมือถือบ้าง บางทีก็ในหน้าต่างแชตนี้ บางทีก็หน้าต่างนั้น มันซับซ้อนเกินไป แล้วทุกครั้งที่เปิดหน้าต่างแชตใหม่ ก็ต้องดึงโพสต์ก่อนหน้ามาและอธิบายว่าทำถึงไหนแล้ว ซึ่งน่าเบื่อมาก

ขอบอกไว้ก่อนว่า งานนี้เป็นส่วนหนึ่งของการสร้างระบบออร์เคสเตรชัน และโพสต์นี้คือบันทึกการทำงานของมัน พูดตรง ๆ ผมคิดว่าเป็นวิธีที่ค่อนข้างไม่มีประสิทธิภาพ คงมีหลายคนสร้างวิธีที่มีประสิทธิภาพกว่านี้มากไว้แล้ว ถึงอย่างนั้นก็ขอเก็บไว้ตรงนี้เพื่อแบ่งปันกระบวนการที่ผมผ่านมา

สิ่งที่ผมต้องการมีอย่างเดียว

วางสมองไว้บนเว็บ แล้วไม่ว่าจะส่งคำขอจากอุปกรณ์ไหน คำขอนั้นต้องผ่านสมอง (GitHub) และทำตามขั้นตอนที่กำหนดไว้ (สกิล เอกสาร md) จนได้ผลลัพธ์ที่สม่ำเสมอ มองจากข้างนอกก็เหมือน "แค่ทำแบบนั้นก็ได้ไม่ใช่เหรอ" แต่มันไม่ง่ายเลย ผมใช้เวลาเกือบหนึ่งสัปดาห์สร้างระบบนี้ หน้าต่างแชตนับไม่ถ้วน การทดสอบนับไม่ถ้วน โทเคนที่เสียไปก็นับไม่ถ้วน และตอนนี้ก็ยังปรับให้ดีขึ้นอยู่

สภาพแวดล้อมของผมเป็นแบบนี้ ปัญหาคือทุกอย่างทำงานแยกกัน

ส่วน สิ่งที่ผมใช้
อุปกรณ์ คอมที่บ้าน คอมที่ทำงาน โน้ตบุ๊ก มือถือ
บัญชี Claude ส่วนตัวสอง ที่ทำงานหนึ่ง รวมสามบัญชี
หน้าต่างแชต แชตในแอปเดสก์ท็อป แท็บ Code เซสชันบนคลาวด์ แอปมือถือ
ผลงาน Kang PD Log เว็บหลายภาษา Cutroom Notes (5 ภาษา) บล็อก Naver

Claude ก็มีหน่วยความจำ แต่มันสะสมแยกกันในแต่ละบัญชี หน่วยความจำของบัญชีหนึ่งมีกฎของบล็อกที่ทำงานปนเข้าไป อีกบัญชีมีกฎของบล็อกส่วนตัว หน้าต่างใหม่เลยทำตามกฎผิดอัน ผมจึงตัดสินใจเก็บความจำไว้นอก Claude ไม่ใช่ข้างใน

สิ่งที่ลองตลอดหนึ่งสัปดาห์

ผมไม่ได้มาถึงโครงสร้างปัจจุบันตั้งแต่แรก ความพยายามที่ล้มเหลวมีมากกว่า

วันที่ สิ่งที่ลอง ผล
10/23 ออกแบบโครงสร้างที่ผมเขียนคำสั่งไว้ในเอกสารเดียวในรีโพซิทอรี แล้วโปรแกรมเฝ้าดูจะตรวจทุก 1–2 ชั่วโมงและส่งงานไปยังหน้าต่างแชตที่รับผิดชอบแต่ละด้าน (บล็อก Naver Premiere) ได้แค่ทิศทาง
10/24 ย้ายคิวงานไปที่ GitHub Issues สร้างป้าย 11 แบบ (ต้องคัดแยก รอ กำลังทำ ติดขัด ตามผู้รับผิดชอบ ตามเครื่อง) แม่แบบ issue และเอกสารกฎการทำงาน โครงตั้งขึ้นแล้ว
10/24 ตั้งงานตามกำหนดเวลา "เซสชันบัญชาการ" ให้ทำงานทุก 2 ชั่วโมงตั้งแต่ 09:00 ถึง 23:00 เพื่อคัดแยกและมอบหมาย issue ใหม่ การคัดแยกทำได้ดี แต่เปิดหน้าต่างแชตผู้รับผิดชอบไม่ได้
10/24 เวิร์กโฟลว์ GitHub Actions ที่แปลอัตโนมัติผ่าน Gemini API ไม่เสถียรเพราะข้อผิดพลาด 429 และ 503 แถมกินโทเคนมากกว่า เลยย้อนกลับ
10/24 เลิกทั้งหมดแล้วรวมเป็นสกิลเดียวที่ทำขั้นตอนที่กำหนดจนจบจากคำสั่งเดียว: "เขียนบล็อกกัน" จุดเริ่มต้นของวิธีปัจจุบัน
10/25 โครงสร้างร่วมสำหรับสามบัญชีและคอมหลายเครื่อง ต้นฉบับอยู่ในรีโพซิทอรีเดียว บัญชีและคอมมีแค่ทางเข้า กระดานเริ่มต้นข้างบนเกิดขึ้นตอนนี้
10/25 เลิกบันทึกลงโฟลเดอร์ในคอมด้วย พื้นที่ทำงานมีแค่ GitHub โครงสร้างปัจจุบัน

ผมคาดหวังกับ Gemini API ไว้พอสมควร คิดว่าถ้าส่งงานอย่างการแปลไปให้โดยไม่ขึ้นกับขีดจำกัดของ Claude ก็น่าจะดี แต่กลายเป็นว่าต้องโน้มน้าวทั้ง Gemini และ Claude ถ้าตัวใดตัวหนึ่งพลาด ปริมาณงานก็เพิ่มเป็นสองเท่า เลยตัดสินใจใช้ Claude อย่างเดียวไปก่อน

ผมยังลองให้งานตามกำหนดเวลาตรวจ Git เป็นระยะ เพื่อให้งานเริ่มเองทุกครั้งที่มีไฟล์เปลี่ยน ปัญหาคือทุกครั้งที่ผมแก้คัมภีร์กฎ (เอกสารกฎการเขียน) มันก็ถูกนับเป็นการเปลี่ยนแปลงและสั่งให้ตรวจ โทเคนรั่วไปเปล่า ๆ ยิ่งไปกว่านั้น เซสชันที่เปิดจากงานตามกำหนดเวลาไม่มีความสามารถในการเปิดหน้าต่างแชตใหม่ ผมรันสองครั้งเพื่อยืนยัน สุดท้ายเลยปิดการเฝ้าดูอัตโนมัติไปในฐานะที่ล้มเหลว ถ้าจะทำก็จะใส่เป็นอย่างสุดท้าย เมื่อออกแบบทั้งหมดเสร็จแล้ว

โครงสร้างปัจจุบัน: ทางเข้าบาง สมองอยู่ในรีโพซิทอรี

แผนภาพนี้ผมวาดเอง หัวใจคือแทบไม่เก็บอะไรไว้ในบัญชีและคอมเลย

ชั้น มีอะไร อยู่ที่ไหน
ทางเข้า คำสั่งสั้น ๆ: ถ้าผมพูดว่า "เชื่อมบล็อก" ให้อ่านรีโพซิทอรีก่อน สกิลหนึ่งตัวต่อบัญชี (blog-connect) และบล็อกคำสั่งส่วนกลางหนึ่งบล็อกในคอมที่ใช้ Claude Code
สมอง คำสั่งเริ่มต้น บันทึกงาน คัมภีร์กฎ สกิลขั้นตอนการเขียน รีโพซิทอรีส่วนตัว blog-notes
ผลงาน โพสต์ คำแปล รูป รีโพซิทอรีสาธารณะสองอัน (Kang PD Log, Cutroom Notes)

ผมไม่เขียนกฎไว้ในทางเข้า ถ้าเขียนไว้ แต่ละบัญชีจะมีเวอร์ชันต่างกัน และทุกการแก้ไขต้องแก้สามที่ งานของทางเข้ามีแค่ "ไปที่รีโพซิทอรีแล้วอ่านตามลำดับนี้" ผมใส่เลขเวอร์ชัน (v1) ให้ทางเข้า ถ้าไม่ตรงกับเลขในคำสั่งเริ่มต้นของรีโพซิทอรี หน้าต่างจะบอกหนึ่งบรรทัดว่า "ช่วยอัปเดตทางเข้าด้วย"

เวลาเพิ่มบัญชีใหม่ ก็แค่ทำตามส่วนนี้ ถ้าหน้าต่างอ่านรีโพซิทอรีไม่ได้ ผมก็วางข้อความสกิลทั้งหมดแล้วลงทะเบียน

นี่คือรีโพซิทอรีส่วนตัวที่ทำหน้าที่เป็นสมอง หน้าต่างใหม่อ่านแค่สิ่งเหล่านี้ ตามลำดับนี้

ลำดับ ไฟล์ อ่านแค่ไหน
1 CLAUDE.md ทั้งหมด คำสั่งเริ่มต้นสั้น ๆ
2 작업일지.md (บันทึกงาน) เฉพาะ "สถานะปัจจุบัน" ห้ามอ่านทั้งไฟล์
3 계획/준구블로그_법전.md (คัมภีร์กฎ) เฉพาะบทที่จำเป็นกับงานตอนนั้น
4 .claude/skills/blog-write เฉพาะส่วนที่เกี่ยวข้องของขั้นตอนการเขียน

ที่ห้ามอ่านทั้งหมดก็เพราะโทเคน อ่านบันทึกงานทั้งไฟล์ทุกครั้งก็กินขีดจำกัดไปแล้ว ตอนจบงาน หน้าต่างต้องแก้ "สถานะปัจจุบัน" ในบันทึกงานแล้ว commit และ push งานที่ยังไม่ push จะไม่ขึ้นในอุปกรณ์อื่น

ระหว่างทางเกิดเหตุจริงด้วย หน้าต่างอื่นหยิบคัมภีร์กฎของบล็อกที่ทำงานไปใช้ทำงาน บนสุดของโฟลเดอร์งานมีเอกสารของที่ทำงานที่ชื่อมีคำว่า "คัมภีร์กฎ" อยู่ เลยโผล่ขึ้นมาก่อนในการค้นหา ผมจึงตอกย้ำไว้ในคำสั่งเริ่มต้นว่า "คัมภีร์กฎของบล็อกเหล่านี้มีไฟล์นี้ไฟล์เดียว" และเพิ่มบรรทัดให้ค้นในคัมภีร์กฎก่อน แทนที่จะถามผมเรื่องกฎอย่างขนาดรูป

อาการที่เจอจริงผมสะสมไว้ทีละอย่างในส่วน "เมื่อใช้ไม่ได้" ของกระดานเริ่มต้น

เก็บ HTML ของกระดานเริ่มต้นไว้ด้วย

รูปบนสุดคือกระดานเริ่มต้นนั้น ทุกครั้งที่เพิ่มบัญชีใหม่หรือคอมเครื่องใหม่ผมสับสน เลยทำเป็น HTML หน้าเดียว มีเจ็ดส่วน: ตอนเปิดแชต ตอนจบงาน ครั้งแรกในบัญชีใหม่ ครั้งแรกในคอมใหม่ ความคืบหน้าปัจจุบัน เมื่อใช้ไม่ได้ และอะไรอยู่ที่ไหน เดิมแต่ละคำสั่งมีแค่ปุ่ม "คัดลอก" ในเวอร์ชันสาธารณะผมเอาปุ่มออกแล้วบันทึกใหม่ให้เห็นคำสั่งและข้อความทั้งหมด

เปิดกระดานเริ่มต้นเวอร์ชันสาธารณะ

เป็นสภาพ ณ ช่วงกลางวันของวันที่ 25 ตุลาคม หลังจากนั้นเปลี่ยนอีกครั้งเป็น "ไม่บันทึกลงโฟลเดอร์ในคอม ใช้แค่ GitHub" เส้นทางโฟลเดอร์ในคอมหรือคำสั่ง push ผ่าน PowerShell บนกระดานจึงแทบไม่ได้ใช้แล้ว บางจุดที่เกี่ยวกับที่ทำงานผมเปลี่ยนเป็นคำทั่วไป

นี่คือรีโพซิทอรีสาธารณะที่ผลงานไปกองรวมกัน ในประวัติ commit มีชื่อผมกับ claude อยู่ด้วยกัน ไม่ว่าทำงานจากหน้าต่างไหน ผลลัพธ์ก็มารวมที่นี่

โพสต์นี้ก็เขียนด้วยโครงสร้างนั้น วันนี้ผมแค่พูดว่า "เขียนบล็อกกัน" ในหน้าต่างแชตใหม่ หน้าต่างอ่านสกิลทางเข้า ดึงรีโพซิทอรีจาก GitHub อ่านบันทึกงาน แล้วรายงานงานถัดไปในบรรทัดเดียว ไม่ได้ถามว่าบล็อกไหน ตอนดึงรีโพซิทอรีครั้งแรกติดไปหนึ่งครั้งเพราะไม่มีการยืนยันตัวตน แล้วดึงใหม่ด้วยการเพิ่มรีโพซิทอรีเข้าเซสชัน จุดติดขัดเล็ก ๆ แบบนี้ยังเหลืออยู่

ที่เหลือคือการเฝ้าดูอัตโนมัติ ตอนนี้ผมยังต้องเปิดหน้าต่างและพูดหนึ่งประโยค เมื่อออกแบบทั้งหมดเสร็จ ค่อยลองใส่เป็นอย่างสุดท้าย
