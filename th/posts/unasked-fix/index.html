28 ตุลาคม 2026

Claude สร้างเครื่องมือใหม่ที่ผมไม่เคยสั่ง ผมเลยย้อนรอยวิธีคิดของมันผ่านบันทึก

อ่านในภาษาอื่น: English · Bahasa Indonesia · हिन्दी · العربية

พอเห็นการปรับปรุงที่ Claude ทำโดยไม่มีใครสั่ง ผมรู้สึกว่ามันพัฒนาขึ้นเอง แต่พอย้อนรอยบันทึกกลับไป กลับพบว่าทิศทางนั้นผมเป็นคนกำหนด และ Claude แค่อุดช่องว่างตรงที่ทิศทางนั้นชนกับเครื่องมือเก่า

ผมแค่บอกว่า "ย้ายไป Naver"

เช้ามืดวันที่ 28 ตุลาคม ผมขอให้ Claude ย้ายตอนที่ 1 ถึง 4 ของซีรีส์วิดีโองานแต่งงานไปลงบล็อก Naver สิ่งที่ผมพูดมีแค่ "ย้ายไป Naver ด้วย"

ท้ายรายงานที่บอกว่าบันทึกฉบับร่างครบสี่ตอนแล้ว มีอีกบรรทัดหนึ่งต่อท้าย เครื่องมือป้อนข้อมูลตัวเก่าต้องใช้โฟลเดอร์ในพีซีของผมกับเซิร์ฟเวอร์ภายในเครื่องถึงจะทำงานได้ Claude เลยสร้างเครื่องมือใหม่ที่อ่านฉบับร่างและรูปภาพจาก GitHub โดยตรง

ประวัติคอมมิตของเครื่องมือป้อนข้อมูลตัวใหม่ อันล่างสุดคือรุ่นแรก แต่ละอันที่อยู่ข้างบนแก้จุดที่ติดเพิ่มทีละจุด

ระหว่างตีหนึ่งสิบเอ็ดนาทีถึงตีหนึ่งสิบแปดนาที โพสต์ทั้งสี่เข้าไปทีละโพสต์ โพสต์วันที่ 27 ตุลาคมด้านล่างคือฉบับสั้นตัวเก่า

ผมไม่เคยสั่งเรื่องนั้น ผมเลยคิดว่า Claude พัฒนามันขึ้นมาเอง ดูเหมือนมันรู้เองว่าวิธีเก่าไม่สะดวก แล้วก็สร้างวิธีที่ดีกว่าขึ้นมาเอง

สิ่งที่ผมอยากรู้คือกระบวนการ มันมองว่าอะไรยังขาด และการตัดสินใจนั้นไหลไปตามลำดับแบบไหน ผมจึงถาม Claude ในหน้าต่างแชตถัดไป

ทิศทางนั้นผมเป็นคนกำหนดเอง

สิ่งแรกที่ Claude ชี้คือข้อสันนิษฐานของผมผิดไปครึ่งหนึ่ง พอเทียบคอมมิตกับบันทึกการทำงาน การตัดสินใจเอาพีซีออกจากขั้นตอนเป็นสิ่งที่ผมตัดสินใจเองเมื่อสามวันก่อน

วันที่ สิ่งที่เปลี่ยน ใคร
25 ต.ค. พื้นที่ทำงานใช้ GitHub อย่างเดียว ห้ามบันทึกหรือ pull ในโฟลเดอร์พีซี คำสั่งของผม
26 ต.ค. สกิลของบัญชีเหลือแค่ตัวชี้ทาง กฎย้ายไปอยู่ในรีโพสิทอรี คำสั่งของผม
26 ต.ค. วิธีใส่รูปด้วยการวางเมื่ออัปโหลดไฟล์ถูกบล็อก หน้าต่างที่ติดอยู่หาเจอ
28 ต.ค. เครื่องมือป้อนข้อมูล Naver ตัวใหม่ที่อ่านฉบับร่างและรูปจาก GitHub Claude โดยไม่มีใครสั่ง

การแก้เอกสารกฎเมื่อ 25 ตุลาคม บรรทัดตรวจพีซีถูกเอาออก แล้ว "พื้นที่ทำงานคือ GitHub เท่านั้น" ก็เข้ามาแทน

ปัญหาคือมีแค่กฎที่เปลี่ยน แต่เครื่องมือยังเหมือนเดิม กฎห้ามเปิดโฟลเดอร์ในพีซี แต่เครื่องมือป้อนข้อมูล Naver ยังต้องใช้รูปในโฟลเดอร์พีซีกับเซิร์ฟเวอร์ภายในเครื่อง (พอร์ต 8125) ที่เปิดอยู่บนพีซี

ระหว่างนั้นแต่ละหน้าต่างก็หาทางอ้อมเอาเองด้วยมือ วันที่ 26 ตุลาคม หน้าต่างหนึ่งวาดรูปปกในเบราว์เซอร์บนพีซีโดยตรง แล้ววางรูปทีละรูปจากที่อยู่สาธารณะของมัน

ลำดับการตัดสินใจที่ Claude อธิบาย

มีเรื่องหนึ่งที่ต้องบอกก่อน หน้าต่างแชตที่สร้างเครื่องมือใหม่ถูกปิดไปแล้ว และมันไม่ได้จดไว้ว่าทำไมถึงทำแบบนั้น Claude ในหน้าต่างปัจจุบันก็มองเข้าไปในการตัดสินใจนั้นไม่ได้ จึงย้อนรอยจากการกระทำที่เหลืออยู่ในบันทึกบทสนทนาและลำดับของคอมมิต

Claude อธิบายจุดเริ่มต้นว่าเป็น ความขัดแย้ง ไม่ใช่ความไม่พอใจ การย้ายต้องใช้เครื่องมือป้อนข้อมูล แต่การใช้เครื่องมือนั้นหมายถึงการผิดกฎ มันบอกว่าตอนนั้นมีทางให้เลือกสามทาง

ทาง ผลลัพธ์
หยุดแล้วถาม งานหยุดรอคำตอบกลางดึก และกฎเองก็บอกว่าอย่าหยุด ให้ใส่คิวไว้
วิธีเก่า ผิดกฎ
หาทางใหม่ ทดสอบครั้งเดียวก็รู้ว่าได้หรือไม่ได้

นั่นคือเหตุผลที่มันเลือกทางที่สาม การคาดว่าเบราว์เซอร์ที่ล็อกอิน GitHub อยู่จะดึงไฟล์จากรีโพสิทอรีส่วนตัวได้ ได้รับการยืนยันทันทีด้วยการเปิดที่อยู่สองแห่ง มันบอกว่าถ้าเปิดไม่ได้ ตามกฎก็จะใส่แค่ฉบับร่างไว้ในคิว

ที่เหลืออยู่ในบันทึกทั้งหมด

ลำดับ การกระทำในบันทึก คำอธิบายของ Claude
1 อัปโหลดฉบับร่าง 4 ตอนและรูปปกขึ้น GitHub ก่อน วัตถุดิบต้องอยู่ในรีโพสิทอรี ไม่ใช่บนพีซี ถึงจะตรงกับกฎ
2 เปิดไฟล์สองไฟล์จากรีโพสิทอรีส่วนตัวใน Whale ทดสอบที่ถูกที่สุดก่อน
3 อ่านเครื่องมือปรับขนาดรูปแล้วเขียนเครื่องมือใหม่ ใช้ส่วนที่ทำงานได้อยู่แล้วซ้ำ (สไตล์ตาราง 2 ขนาดรูป ฟอนต์)
4 ใส่รูปไม่สำเร็จสองครั้ง → เปลี่ยนเป็นการวาง Playwright ดักหน้าต่างเลือกไฟล์ไว้ จึงใช้วิธีที่อีกหน้าต่างจดไว้เมื่อสองวันก่อน
5 คอมมิตหกครั้งระหว่างตีหนึ่งสามนาทีถึงตีหนึ่งสิบสองนาที รัน แก้จุดที่ติดหนึ่งจุด แล้วรันใหม่
6 วิธีใช้หนึ่งบรรทัดในสกิล ให้หน้าต่างถัดไปไม่หลงที่จุดเดิม

รายการคอมมิตด้านบนคือลำดับที่ 5 ภายในเก้านาที รุ่นแรกถูกแก้เพิ่มอีกห้าครั้ง

ยังเหลือช่องว่างอยู่หนึ่งจุด

หน้าต่างที่สร้างเครื่องมือใหม่เพิ่มวิธีใช้หนึ่งบรรทัดลงในสกิล แต่ไม่ได้ลบขั้นตอนเก่าออก ในสกิลจึงมีขั้นตอนเก่าที่ใช้โฟลเดอร์พีซีกับเซิร์ฟเวอร์ภายในเครื่องวางอยู่ข้างเครื่องมือใหม่ หน้าต่างถัดไปที่อ่านแค่สกิลอาจกลับไปใช้ทางเก่าได้

คนที่เจอคือหน้าต่างที่กำลังเขียนโพสต์นี้ ตอนผมถามว่าสกิลเปลี่ยนแล้วใช่ไหม มันชี้ขึ้นมาก่อนว่าคำสั่งเริ่มต้นกับสกิลพูดไม่ตรงกัน ผมบอกให้จัดการ มันก็แก้ตรงนั้นเลย

คำสั่งเริ่มต้นที่แก้วันนี้ บรรทัดที่เคยสั่งให้เปิดเซิร์ฟเวอร์ภายในเครื่องตอนนี้เขียนว่า "ไม่จำเป็น"

ช่องว่างที่หน้าต่างหนึ่งอุดไว้ หน้าต่างถัดไปก็อุดต่อจนเสร็จ

คำที่ตรงกว่า "พัฒนา"

ผมถามด้วยว่าคำว่า "พัฒนา" ใช้ถูกไหม Claude บอกว่าไม่ คำว่า "พัฒนา" ฟังเหมือน Claude ฉลาดขึ้น ทั้งที่โมเดลยังเหมือนเดิม และพอเปลี่ยนหน้าต่าง มันก็จำเรื่องตอนนั้นไม่ได้ด้วยซ้ำ

สิ่งที่เปลี่ยนคือรีโพสิทอรี เอกสารกฎ เครื่องมือป้อนข้อมูลตัวใหม่ และบรรทัดหนึ่งที่เหลือไว้ในสกิลสะสมกันขึ้นมา และหน้าต่างถัดไปก็เริ่มจากการอ่านสิ่งเหล่านั้น

คำที่ Claude เลือกจึงเป็น "การปรับปรุงที่ไม่มีใครสั่ง" หรือสั้นกว่านั้นคือ "อุดช่องว่าง" Claude สรุปไว้แบบนี้ ผมกำหนดทิศทาง Claude อุดจุดที่ทิศทางกับความเป็นจริงไม่ตรงกัน และสิ่งที่อุดไว้ก็อยู่ในรีโพสิทอรี มันบอกว่ารีโพสิทอรีที่ผมเรียกว่า สมองของ AI นั่นแหละที่เติบโตขึ้น
