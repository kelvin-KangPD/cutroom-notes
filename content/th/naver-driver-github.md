พอผมฝากงานย้ายไป Naver ให้ Claude มันก็เปลี่ยนเครื่องมือป้อนข้อมูลที่ต้องพึ่งโฟลเดอร์พีซีและเซิร์ฟเวอร์ในเครื่อง ให้มาอ่านฉบับร่างและรูปจาก GitHub โดยตรง ตอนนี้พีซีขอแค่หน้าต่างเบราว์เซอร์ Whale ที่ล็อกอินไว้หนึ่งหน้าต่างก็พอ

เช้ามืดวันที่ 28 ตุลาคม ผมขอให้ Claude ย้ายตอนที่ 1 ถึง 4 ของซีรีส์วิดีโองานแต่งไปลง Naver ระหว่างบันทึกฉบับร่างทั้งสี่ตอน Claude เขียนเครื่องมือป้อนข้อมูลใหม่ และพอเสร็จงานก็บอกเรื่องนี้ไว้หนึ่งบรรทัดท้ายรายงาน

![หน้าประวัติคอมมิตของ GitHub: คอมมิตหกรายการที่ขึ้นต้นด้วย "เครื่องมือป้อนข้อมูล Naver รุ่น GitHub" เรียงซ้อนจากบนลงล่าง](/images/20261028-naver-driver-github/01-입력기-커밋-여섯-판.webp)
<small>ประวัติคอมมิตของเครื่องมือป้อนข้อมูลตัวใหม่ อันล่างสุดคือรุ่นแรก แต่ละอันข้างบนแก้จุดที่ติดเพิ่มทีละจุด</small>

เครื่องมือป้อนข้อมูลคือสคริปต์ที่สั่งเบราว์เซอร์ Whale ผ่าน Playwright เพื่อใส่โพสต์ลงในโปรแกรมแก้ไขของ Naver ถ้า Playwright คือมือ เครื่องมือป้อนข้อมูลก็คือใบลำดับงานที่ยื่นให้มือนั้น มันอ่านฉบับร่างแล้วกำหนดว่าจะใส่ชื่อเรื่อง หัวข้อย่อยแบบคำพูดอ้างอิง ตาราง และรูปตามลำดับไหน ครั้งนี้สิ่งที่เปลี่ยนไม่ใช่มือ แต่เป็นใบลำดับงาน

## กฎบอกว่า GitHub อย่างเดียว แต่เครื่องมือยังผูกอยู่กับพีซี

วันที่ 25 ตุลาคม ผมกำหนดให้ GitHub เป็นพื้นที่ทำงานเดียวของบล็อก เพื่อให้เปิดจากบัญชีไหน พีซีเครื่องไหน หรือมือถือ งานก็ต่อจากสถานะเดียวกัน ผมจึงเพิ่มกฎไว้ในคำสั่งเริ่มต้นว่า ห้ามบันทึกหรือ pull ในโฟลเดอร์พีซี

![หน้าเปรียบเทียบคอมมิตของ GitHub: ในคำสั่งเริ่มต้น บรรทัด "การตรวจพีซีและสิทธิ์" ถูกลบเป็นสีแดง และ "พื้นที่ทำงานคือ GitHub เท่านั้น" ถูกเพิ่มเป็นสีเขียว](/images/20261028-naver-driver-github/02-작업공간-규칙-변경.webp)
<small>การแก้คำสั่งเริ่มต้นเมื่อ 25 ตุลาคม บรรทัดตรวจพีซีถูกเอาออก แล้ว "พื้นที่ทำงานคือ GitHub เท่านั้น" ก็เข้ามา</small>

แต่เครื่องมือป้อนข้อมูล Naver ยังทำงานแบบเดิม การรันเครื่องมือตัวเก่า (`naver_driver.js`) ต้องเตรียมบนพีซีแบบนี้

| การเตรียม | เครื่องมือตัวเก่า |
|---|---|
| ฉบับร่าง | อ่านผ่านเซิร์ฟเวอร์ในเครื่องที่เปิดด้วย `python -m http.server 8125` ในโฟลเดอร์ blog-notes บนพีซี |
| รูป | คัดลอกไปไว้ในโฟลเดอร์พีซีที่ Playwright อนุญาต ตั้งชื่อ `up0.webp` `up1.webp` |
| ตั้งค่า | คัดลอกเครื่องมือไว้ในโฟลเดอร์เดียวกันชื่อ `drv.js` แล้วเขียนชื่อฉบับร่างและตำแหน่งเริ่มใน `naver_params.json` |
| ใส่รูป | พอหยุดที่รูป ก็อัปโหลดด้วย `browser_file_upload` แล้วรันใหม่ |

ตามกฎแล้ว ขั้นตอนไหนที่ใช้โฟลเดอร์พีซีก็ทำไม่ได้ทั้งหมด สองวันก่อนตอนเขียนโพสต์รีวิว Coupang หน้าต่างบนคลาวด์ก็อ้อมปัญหานี้ด้วยมือ มันวาดรูปปกบนแคนวาสในเบราว์เซอร์ของพีซี แล้ววางรูปทีละรูปจากที่อยู่สาธารณะบน Kang PD Log

## ทดสอบด้วยที่อยู่สองแห่งก่อน

Claude อัปโหลดฉบับร่างสี่ตอนและรูปปกขึ้นรีโพสิทอรีส่วนตัวบน GitHub ก่อน เพราะวัตถุดิบต้องอยู่ในรีโพสิทอรี ไม่ใช่บนพีซี ถึงจะตรงกับกฎ

จากนั้นแทนที่จะสร้างเครื่องมือทันที มันทดสอบก่อน Whale ล็อกอินบัญชี GitHub ของผมอยู่ แล้ว Whale จะดึงไฟล์จากรีโพสิทอรีส่วนตัวได้ด้วยไหม มันขอที่อยู่สองแห่งผ่าน Whale คือรูปปกหนึ่งรูปกับฉบับร่างหนึ่งไฟล์ และได้มาทั้งคู่

**การทดสอบครั้งเดียวนั้นทำให้ไม่ต้องใช้โฟลเดอร์พีซีอีกเลย** ฉบับร่างและรูปปกมาจากรีโพสิทอรีส่วนตัว ส่วนรูปในเนื้อหามาจากที่อยู่ของ Kang PD Log ที่เผยแพร่แล้ว ส่วนหัวของฉบับร่างแค่เพิ่มชื่อโฟลเดอร์รูป (`imgdir`) หนึ่งบรรทัด

| วัตถุดิบ | เครื่องมือใหม่เอามาจากไหน |
|---|---|
| ฉบับร่าง | รีโพสิทอรีส่วนตัว blog-notes `네이버/*.md` |
| รูปปก | รีโพสิทอรีเดียวกัน `네이버/썸네일/<slug>.webp` |
| รูปในเนื้อหา | ที่อยู่สาธารณะของ Kang PD Log `images/<imgdir>/` |
| ตัวเครื่องมือเอง | รีโพสิทอรีเดียวกัน `tools/naver_driver_gh.js` ล็อกด้วยเลขคอมมิต |

ตัวเครื่องมือเองก็อ่านจาก GitHub วิธีคือบอก Whale ว่า "ไปเอาเครื่องมือป้อนข้อมูลจากคอมมิตนี้แล้วรัน" พอล็อกเลขคอมมิตไว้ ทุกครั้งที่แก้ก็แค่อัปโหลดคอมมิตใหม่แล้วเรียกด้วยเลขใหม่

```js
async (page) => {
  const SHA = '<커밋 번호>';
  const s = await (await page.request.get('https://github.com/kelvin-KangPD/blog-notes/raw/' + SHA + '/tools/naver_driver_gh.js')).text();
  return await eval(s)(page, { SHA, FILE: '<원고 파일>', PHASE: 'write', START: 0, CLEAR: true });
}
```

โค้ด Playwright แต่ละครั้งต้องจบภายใน 60 วินาที เครื่องมือจึงคืนเลขที่หมายถึง "ใส่ถึงตรงนี้แล้ว" เมื่อครบ 40 วินาทีแล้วหยุด เรียกต่อจากเลขนั้นก็ใส่ต่อได้ พอใส่เนื้อหาครบ ก็เรียกขั้นปิดงานแยกต่างหาก เพื่อใช้สไตล์ "ตาราง 2" ปรับขนาดรูป (รูปหลักกว้าง 600 รูปที่ถูกยืดกลับเป็นความกว้างเดิม) ตั้งฟอนต์เนื้อหาเป็น NanumSquare และบันทึกฉบับร่าง

## ติดที่รูปสองครั้ง

พอรันรุ่นแรก สิ่งที่ติดคือรูป ภายในเก้านาทีมีคอมมิตสะสมหกรายการ

| เวลา | สิ่งที่เปลี่ยน | เหตุผล |
|---|---|---|
| 1:03 | รุ่นแรก | อ่านฉบับร่างและรูปจาก GitHub โดยไม่ใช้โฟลเดอร์พีซีหรือเซิร์ฟเวอร์ในเครื่อง |
| 1:04 | ใส่รูปผ่านหน้าต่างเลือกไฟล์ | ใส่ไฟล์ลงช่องอินพุตโดยตรงไม่ได้ผล |
| 1:06 | ใส่รูปด้วยอีเวนต์วาง | Playwright ดักหน้าต่างเลือกไฟล์ไว้ จึงใช้ไม่ได้ |
| 1:06 | ไม่เปิดซ้ำถ้าอยู่หน้าเขียนอยู่แล้ว | ทุกครั้งที่เปิดซ้ำจะมีกล่อง "ออกจากหน้านี้ไหม" เด้งขึ้นมา |
| 1:09 | จับเคอร์เซอร์ก่อนใส่รูปและเช็กตำแหน่ง | ถัดจากตารางหรือรูปทันที เคอร์เซอร์ไม่ติด รูปเลยไปอยู่บนสุดของโพสต์ |
| 1:12 | ล้างเนื้อหาให้หมดและรอรูปนานขึ้น | กันไม่ให้เริ่มทั้งที่โพสต์ยังล้างไม่หมด และไม่ไปต่อก่อนรูปเข้าครบ |

วิธีวางนี้เป็นสิ่งที่หน้าต่างแชตอีกหน้าต่างหาเจอเมื่อสองวันก่อนและจดไว้ในสกิล ถ้าสร้างรูปเป็นออบเจกต์ไฟล์ในโปรแกรมแก้ไข แล้วส่งไปพร้อมสัญญาณ "เพิ่งมีการวาง" โปรแกรมแก้ไขของ Naver ก็รับรูปเหมือนคนกด Ctrl+V พอติด Claude ก็หยิบบันทึกนั้นมาใส่ในเครื่องมือ

ปัญหาเคอร์เซอร์ยังเขียนไว้ในคอมเมนต์ของเครื่องมือ ทันทีที่ใส่ตาราง โปรแกรมแก้ไขย้ายเคอร์เซอร์ออกจากตารางไม่ได้ รูปเลยไปตกอยู่บนสุดของโพสต์ ตอนนี้จับเคอร์เซอร์ด้วยการพิมพ์ตัวอักษรหนึ่งตัวแล้วลบ และหลังใส่รูปจะเช็กว่าบล็อกสุดท้ายเป็นรูปหรือไม่ ถ้าไม่ใช่ก็หยุด

## สี่โพสต์เข้าไปภายในเจ็ดนาที

ด้วยรุ่นที่หก ตอนที่ 1 ถึง 4 เข้าไปทีละตอน ตอนที่ 1 บันทึกตอนตีหนึ่งสิบเอ็ดนาที ตอนที่ 4 ตอนตีหนึ่งสิบแปดนาที

![รายการฉบับร่างที่บันทึกไว้ในบล็อก Naver: วิดีโองานแต่งตอนที่ 1 ถึง 4 บันทึกระหว่าง 1:11 ถึง 1:18 วันที่ 28 ตุลาคม และมีโพสต์วันที่ 27 ตุลาคมหนึ่งโพสต์อยู่ล่างสุด](/images/20261028-naver-driver-github/03-네이버-임시저장-네-편.webp)
<small>รายการฉบับร่าง ตอนที่ 1 ถึง 4 เข้าไปต่อกันภายในเจ็ดนาที โพสต์วันที่ 27 ตุลาคมด้านล่างคือฉบับสั้นตัวเก่า</small>

**บนพีซีไม่ต้องเตรียมอะไรเลย** ไม่ได้เปิดเซิร์ฟเวอร์ ไม่ได้คัดลอกรูป ขอแค่หน้าต่าง Whale เปิดอยู่และล็อกอิน Naver กับ GitHub ไว้ก็จบ

พอเสร็จงาน Claude เขียนวิธีใช้เครื่องมือใหม่หนึ่งบรรทัดลงในสกิล แต่ขั้นตอนเก่าของเครื่องมือตัวเก่ายังค้างอยู่ ไม่กี่ชั่วโมงต่อมาอีกหน้าต่างหนึ่งชี้ว่าคำสั่งเริ่มต้นกับสกิลพูดไม่ตรงกัน และพอผมบอกให้จัดการ มันก็เอาขั้นตอนเก่าออก

![หน้าเปรียบเทียบคอมมิตของ GitHub: ในคำสั่งเริ่มต้น บรรทัด "เซิร์ฟเวอร์ในเครื่อง" ที่สั่งให้เปิดเซิร์ฟเวอร์ถูกลบ แล้วเปลี่ยนเป็น "ไม่จำเป็น"](/images/20261028-naver-driver-github/04-시작-지침-정리.webp)
<small>คำสั่งเริ่มต้นหลังจัดการแล้ว บรรทัดที่เคยสั่งให้เปิดเซิร์ฟเวอร์ในเครื่องตอนนี้เขียนว่า "ไม่จำเป็น"</small>

## พีซีให้ยืมแค่หน้าต่าง Whale หน้าต่างเดียว

ในโครงสร้างตอนนี้ หน้าที่ของพีซีมีแค่เบราว์เซอร์ที่ล็อกอินไว้ งานทำในหน้าต่างบนคลาวด์ และยืม Whale บนพีซีเฉพาะตอนจำเป็น

| งาน | ทำที่ไหน |
|---|---|
| ฉบับร่าง รูปปก แปลงรูป เผยแพร่บน Kang PD Log และเว็บหลายภาษา | หน้าต่างบนคลาวด์ (รีโพสิทอรี GitHub) |
| บันทึกฉบับร่าง Naver | หน้าต่าง Whale บนพีซี (เครื่องมือใหม่อ่านจาก GitHub แล้วใส่) |
| จับภาพหน้าจอเว็บ | ถ่ายในหน้าต่าง Whale บนพีซีแล้วส่งกลับมาที่คลาวด์ |
| ตอนที่ Whale ปิดอยู่ | ทำแค่ฉบับร่างแล้วใส่คิวไว้ใน `네이버/대기열.md` |

ภาพหน้าจอในโพสต์นี้ก็ได้มาแบบเดียวกัน Whale ถ่ายหน้าจอ GitHub แล้วส่งข้อมูลภาพกลับมาเป็นตัวอักษร จากนั้นฝั่งคลาวด์ก็แปลงกลับเป็นไฟล์รูป ฟอนต์ที่ใช้ทำรูปปกดาวน์โหลดจากคลาวด์ไม่ได้เพราะที่อยู่ถูกบล็อก Whale เลยไปเอามาแล้วส่งให้เป็นสองส่วน

ตรงจุดที่กฎกับเครื่องมือไม่ตรงกัน มันไม่หยุดและไม่ผิดกฎ แต่เช็กด้วยการทดสอบราคาถูกก่อนว่ามีทางไหม แล้วค่อยแก้ทีละเรื่องจนใส่ครบทั้งสี่โพสต์ งานนี้ Claude ทำได้ดี
