ซับไตเติลของวิดีโอทริปยาว 62 ชั่วโมง ผมเปลี่ยนวิธีเป็นใช้การถอดเสียงของ Premiere หาตำแหน่งที่มีคนพูด แล้วขัดเกลาด้วย Gemini เฉพาะช่วงไฮไลต์
**ส่วนงานของ AI ต้นทุนขึ้นอยู่กับความยาวของบทสนทนาและจำนวนครั้งที่โต้ตอบกันไปมา**

นี่คือตอนสุดท้ายของบันทึกการทำงาน ว่าด้วยซับไตเติล ต้นทุน และฟุตเทจเก่าที่จัดไปพร้อมกัน

## ซับไตเติล: การถอดเสียงของ Premiere + Gemini

ซับไตเติลไฟล์ SRT จาก Gemini แม่นที่สุด แต่จะใส่ทั้ง 62 ชั่วโมงเข้า Gemini ไม่ได้ ผมเลยเปลี่ยนวิธี

| ขั้น | รายละเอียด |
|---|---|
| 1 | ส่งออกซีเควนซ์รายวันเป็น MP3 ด้วย Media Encoder |
| 2 | รันการถอดเสียงของ Premiere ก่อนเพื่อหาตำแหน่งที่มีคนพูด ภาษาตั้งต้นเป็นภาษาอังกฤษ เลยเปลี่ยนเป็นภาษาเกาหลี |
| 3 | ตัดช่วงที่ระบบจำไม่ได้ออกจากผลถอดเสียง (JSON) ซึ่งช่วยกรองเสียงวิทยุสื่อสารระหว่างซาฟารีออกไป |
| 4 | สร้าง SRT จาก JSON แล้วใส่เป็นแทร็กคำบรรยายในซีเควนซ์ v2 ผ่าน MCP |
| 5 | ขัดเกลาด้วย Gemini เฉพาะช่วงที่จะใช้ตัดต่อจริง ไม่ใช่ทั้งหมด เลือกช่วงไฮไลต์ที่มีบทสนทนาหนาแน่นด้วยการให้คะแนน แล้วแบ่งเป็นท่อนละ 2 นาที แอป Gemini ถอดเสียงได้ครบจนจบแค่ราว 2 นาที เลยลดลงมาจากท่อนละ 3 นาทีที่ใช้ตอนแรก |

![บล็อกซับไตเติลเรียงอยู่บนแทร็กคำบรรยาย C1 ด้านบนสุดของไทม์ไลน์ Premiere](/images/20261019-captions-efficiency/01-caption-track.webp)
*C1 ด้านบนสุดของซีเควนซ์ v2 คือแทร็กคำบรรยาย เพราะเป็นคำบรรยายไม่ใช่คลิปข้อความ จึงส่งออกเป็น SRT ใหม่หรือแก้ไขทีหลังได้ง่าย*

การถอดเสียง ผมตั้งคิวไว้ใน Premiere ทีละวันแล้วปล่อยให้รันเอง ตอนแรก AI เช็กทุก 3 นาทีและจัดการทีละรายการ แต่การทบทวนกลางทางพบว่าไม่คุ้ม เลยเปลี่ยนเป็นรวบจัดการวันที่เสร็จแล้วทุก 30–40 นาที

ผมยังลองให้ส่งการแจ้งเตือนเข้าโทรศัพท์เมื่องานเสร็จ ฝั่ง AI บอกว่าส่งไปหลายครั้ง แต่ไม่มีมาถึงสักครั้ง สุดท้ายเลยตัดสินใจเข้าไปดูเองบ่อยๆ

## ต้นทุนและประสิทธิภาพ

ครั้งนี้เป็นครั้งแรกที่ผมใส่ใจเรื่องปริมาณการใช้งานจริงจัง
ทุกครั้งที่ส่งคำสั่ง AI จะอ่านบทสนทนาทั้งหมดจนถึงตอนนั้นใหม่อีกรอบ ยิ่งบทสนทนายาว งานเดียวกันก็ยิ่งแพงขึ้นหลายเท่า
การรอ 20 นาทีแทบไม่เสียอะไร ที่แพงคือการโต้ตอบไปมาหลายครั้ง

ระหว่างทางผมถามว่าวิธีที่ทำอยู่คุ้มไหม คำตอบคือครึ่งๆ

| งาน | การประเมิน |
|---|---|
| กู้เวลาของ GoPro | ใช้สคริปต์สองสามครั้งปรับได้หลายสิบไฟล์ในทีเดียว และผ่านการตรวจสอบตั้งแต่รอบแรก |
| จัดที่เก็บโปรเจกต์ | เสร็จในไม่กี่ขั้น |
| ตรวจเวลาของ Canon | ไม่คุ้ม พยายามดึงเสียงจากฮาร์ดดิสก์ภายนอกทั้งลูกแล้วต้องเลิกเพราะช้า รับบันทึกข้อผิดพลาดยาว 260,000 ตัวอักษรมาทั้งก้อน และเชื่อสมมติฐานที่ยังไม่ได้ตรวจจนรันการเทียบเสียงไปสองรอบ ทั้งที่ดูรูปเดียวก็รู้ได้ทันที |

ตอนท้ายจึงให้เขียนเอกสารส่งต่องานไว้ในโฟลเดอร์งาน แล้วตกลงกันว่าจะย้ายไปบทสนทนาใหม่ในเวลาที่โควตาการใช้งานรีเซ็ต
มันเขียนข้อความแรกสำหรับวางในบทสนทนาใหม่ไว้ให้ด้วย

```
อ่านเอกสารส่งต่องานในโฟลเดอร์ตัดต่อแทนซาเนียบนคอมพิวเตอร์ที่บ้าน (ไดรฟ์ I:) แล้วตัดต่อแทนซาเนียต่อ
ขอสิทธิ์ที่ต้องใช้ทั้งหมดในครั้งเดียวตั้งแต่ต้น และทำงานแบบขนาน
```

ในเอกสารส่งต่องานยังใส่เคล็ดลับที่ได้เรียนรู้ครั้งนี้ไว้ด้วย

| เคล็ดลับ | รายละเอียด |
|---|---|
| อ่านฮาร์ดดิสก์ภายนอก | ช้า อย่าอ่านทั้งไฟล์ อ่านเฉพาะช่วงที่ต้องใช้ |
| ผลลัพธ์ | รับแค่สรุป ถ้าบันทึกพรั่งพรูออกมา ทั้งหมดนั้นคือต้นทุน |
| การตรวจสอบ | ก่อนรันอะไรนานๆ ให้ทดสอบสมมติฐานกับตัวอย่างเดียวก่อน |
| คัดลอกจำนวนมาก | 7-Zip File Manager เร็วกว่าคัดลอกด้วยคำสั่ง |
| ซิงก์เสียง | เทียบความดังเบาของเสียงที่เปลี่ยนไปในสองคลิปเพื่อจับให้ตรงกัน |

## ฟุตเทจเก่าก็จัดเป็นโครงเดียวกัน

ไม่ได้จัดแค่วิดีโอทริป โฟลเดอร์ฟุตเทจส่วนตัวที่ถ่ายไว้ก่อนทริป 14 โฟลเดอร์ ผมก็จัดให้เป็นโครงเดียวกัน

| รายการ | รายละเอียด |
|---|---|
| โครงสร้าง | ต้นฉบับ\วิดีโอ, ต้นฉบับ\รูปถ่าย, อื่นๆ, โปรเจกต์ |
| กฎ | วิดีโอและเสียงไว้ในต้นฉบับ\วิดีโอ รูปไว้ในต้นฉบับ\รูปถ่าย งานที่แปรรูปแล้วอย่างไฟล์ปรับแต่งและกราฟิกไว้ในอื่นๆ ไฟล์โปรเจกต์ไว้ในโปรเจกต์ |
| การตรวจสอบ | ตรวจว่าจำนวนไฟล์เท่ากับก่อนจัด |
| ไม่ได้แตะ | โฟลเดอร์ที่มีโครงอยู่แล้ว โปรเจกต์ที่กำลังตัดต่อ (กลัวลิงก์พัง) และโฟลเดอร์ที่ไม่มีวันที่ |
| ต่อไป | สร้างโปรเจกต์ให้แต่ละโฟลเดอร์ พร้อมซีเควนซ์ที่แยกแทร็กตามกล้อง |
