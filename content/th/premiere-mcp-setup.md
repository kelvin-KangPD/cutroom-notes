ผมเชื่อมแอป Claude บนเดสก์ท็อปกับ Premiere MCP ให้ AI ควบคุมคอมพิวเตอร์และ Premiere ได้โดยตรง
**แล้วแก้ทั้งกับดักตอนติดตั้งและปัญหาแย่งพอร์ตไปทีละข้อ**

งานในตอนที่ 1 และ 2 ทำได้ก็เพราะการเชื่อมต่อนี้

## เชื่อมอะไร และเชื่อมอย่างไร

ถ้า AI แค่บอกวิธีแล้วผมต้องลงมือเองทั้งหมด ปริมาณขนาดนี้คงทำไม่ไหว

| การเชื่อมต่อ | สิ่งที่ AI ทำ |
|---|---|
| แอป Claude บนเดสก์ท็อป + การเชื่อมต่อระยะไกล | ต่อให้ผมคุยจากโทรศัพท์หรือที่ทำงาน งานก็รันอยู่บนคอมพิวเตอร์ที่บ้าน |
| ไฟล์และคอมมานด์ไลน์ | ดูรายชื่อไดรฟ์ ตรวจผลการคัดลอก ดึงเวลาถ่ายและเสียงด้วย ffmpeg รันสคริปต์ Python |
| ควบคุมหน้าจอ | คลิกใช้งาน 7-Zip, Premiere และ Media Encoder |
| Premiere MCP | สร้างซีเควนซ์และแทร็กคำบรรยาย และบันทึกโปรเจกต์ ผ่านแผงบริดจ์ที่ติดอยู่ใน Premiere |
| Media Encoder | ส่งออกซีเควนซ์รายวันเป็น MP3 สำหรับถอดเสียง |

การควบคุมหน้าจอก็มีข้อจำกัด ใน File Explorer คลิกได้ แต่คัดลอก วาง และลากวางถูกบล็อก อุปกรณ์ที่ไม่มีอักษรไดรฟ์ อย่างโทรศัพท์ ผมเลยต้องย้ายเอง

## Premiere MCP

MCP คือวิธีเชื่อม AI กับโปรแกรมอื่นให้ใช้งานเหมือนเป็นเครื่องมือ
สำหรับ Premiere ผมใช้ Adobe-Premiere-Pro-MCP ที่เผยแพร่บน GitHub ฝั่ง Premiere จะมีแผงส่วนขยาย "MCP Bridge" และมีเซิร์ฟเวอร์เล็กๆ รันอยู่ในเครื่อง (พอร์ต 8097) คอยส่งคำสั่งของ AI ไปเป็นสคริปต์ของ Premiere (ExtendScript)

![แผง MCP Bridge ใน Premiere ขึ้นสถานะ Connected พร้อมบันทึกการเชื่อมต่อ](/images/20261018-premiere-mcp-setup/01-mcp-bridge-connected.webp)
*แผง MCP Bridge ต้องขึ้น Connected สีเขียวก่อน คำสั่งของ AI จึงจะเข้าไปถึง Premiere*

ผมติดตั้งครั้งแรกตอนต้นเดือนกันยายน ระหว่างทำวิดีโอที่ฉายก่อนพิธีแต่งงาน คิดว่าแค่รันตัวติดตั้งก็จบ แต่กับดักเยอะมาก
เดือนตุลาคมติดตั้งในคอมพิวเตอร์ที่ทำงานด้วย และเครือข่ายบริษัทก็มีปัญหาเพิ่มมาอีกหนึ่งข้อ

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| แอป Claude ไม่เปิดเซิร์ฟเวอร์เลย | แอปเวอร์ชัน Microsoft Store อ่านไฟล์ตั้งค่าจากตำแหน่งอื่น | ลงทะเบียนที่ตำแหน่งจริง (ใต้ LocalCache) |
| การตั้งค่าถูกเพิกเฉยแบบเงียบๆ | สคริปต์ติดตั้งใส่ BOM (อักขระที่มองไม่เห็น) ไว้หน้าไฟล์ตั้งค่า | บันทึกใหม่โดยไม่มี BOM |
| เซิร์ฟเวอร์รันไม่ขึ้น | ในการตั้งค่าเขียนแค่ node แอปเลยหาไม่เจอ | ใช้พาธเต็มของ node.exe |
| แผงขึ้น Connected แต่คำสั่งไม่ทำงาน | หน้าต่างแชตแต่ละหน้าต่างเปิดเซิร์ฟเวอร์ของตัวเอง แล้วแย่งพอร์ตเดียวกัน | ปิดโปรเซสเซิร์ฟเวอร์ที่ค้างอยู่แล้วเชื่อมต่อใหม่ |
| คีย์บอร์ดใช้ไม่ได้ใน Premiere | แผงบริดจ์ดึงการกดแป้นไป | ปิดแผงเวลาตัดต่อเอง |
| ติดตั้งในคอมพิวเตอร์ที่ทำงานไม่สำเร็จ | Node ไม่เชื่อใบรับรองของอุปกรณ์ความปลอดภัยของบริษัท | ตัวเลือกให้ Node ใช้คลังใบรับรองของ Windows |

## ลำดับการติดตั้ง

นี่คือลำดับที่สรุปได้หลังติดหลายรอบ ติดตั้งในเครื่องอื่นก็ทำตามนี้ได้

| ขั้น | ที่ไหน | ทำอะไร |
|---|---|---|
| 1 | PowerShell | ตรวจว่าติดตั้ง Node.js แล้ว ถ้ายังให้ติดตั้งแล้วเปิดหน้าต่างใหม่ |
| 2 | เบราว์เซอร์ | ดาวน์โหลด Adobe-Premiere-Pro-MCP จาก GitHub เป็น ZIP แล้วแตกไฟล์ในโฟลเดอร์ Documents ถ้าย้ายทีหลังการเชื่อมส่วนขยายของ Premiere จะพัง จึงควรวางไว้ที่ตำแหน่งสุดท้ายตั้งแต่แรก |
| 3 | Notepad | เปิดอ่าน install.bat ก่อน ถ้ามีการทำงานแปลกๆ นอกจากตั้งค่ารีจิสทรี เชื่อมโฟลเดอร์ส่วนขยาย ติดตั้งและบิลด์แพ็กเกจ และเขียนการตั้งค่า ให้หยุด |
| 4 | PowerShell | รัน install.bat แล้วตรวจว่ามีไฟล์เซิร์ฟเวอร์ (dist\server.js) เกิดขึ้น |
| 5 | Premiere | ปิดให้สนิทแล้วเปิดใหม่ เปิดแผง Window > Extensions > MCP Bridge |
| 6 | แอป Claude | เปิดหนึ่งครั้งแล้วปิด เพื่อให้สร้างโฟลเดอร์การตั้งค่า |
| 7 | PowerShell | ลงทะเบียนเซิร์ฟเวอร์ในไฟล์ตั้งค่าที่ตำแหน่งจริง บันทึกโดยไม่มี BOM และใช้พาธเต็มของ node |
| 8 | PowerShell | ปิดแอป Claude ให้สนิทแล้วเปิดใหม่ แอปอ่านการตั้งค่าแค่ครั้งเดียวตอนเปิด |
| 9 | Premiere | ตรวจว่าแผงขึ้น Connected |
| 10 | แอป Claude | ในแชตใหม่ ตรวจสถานะการเชื่อมต่อ และทดสอบโดยให้อ่านแค่โครงสร้างแทร็กโดยไม่แก้ไขอะไร |

ผมยังกำหนดลำดับการเปิดใช้งานในชีวิตประจำวันไว้ด้วย

| ลำดับ | ทำอะไร |
|---|---|
| 1 | ปิดโปรแกรม MCP อื่นและหน้าต่างแชต Claude อื่น |
| 2 | ถ้ามีเซิร์ฟเวอร์ค้างจับพอร์ต 8097 อยู่ ให้ปิดก่อน |
| 3 | เปิด Premiere เปิดโปรเจกต์และซีเควนซ์ |
| 4 | เปิดแอป Claude (เซิร์ฟเวอร์จะขึ้นเอง) |
| 5 | ตรวจว่าแผงบริดจ์ขึ้น Connected แล้วเริ่มงาน |
| 6 | เวลาตัดต่อเองให้ปิดแผง เซิร์ฟเวอร์ยังทำงานอยู่ เปิดแผงใหม่ก็เชื่อมต่อทันที |

## สุดสัปดาห์นี้: ศึกแย่งพอร์ตกับการแก้บริดจ์

สุดสัปดาห์นี้ปัญหาแย่งพอร์ตก็กลับมาอีก ทุกครั้งที่ย้ายไปหน้าต่างแชตใหม่ เซิร์ฟเวอร์ของหน้าต่างเก่ายังจับพอร์ตไว้ แผงขึ้น Connected แต่คำสั่งหายไปในอากาศ
ตอนแรกผมแก้ขัดด้วยคำสั่ง PowerShell บรรทัดเดียวที่ปิดเซิร์ฟเวอร์ที่ค้างอยู่ทั้งหมด แต่ต้องทำซ้ำทุกครั้งที่ย้ายหน้าต่าง ซึ่งยุ่งยาก
ครั้งนี้ AI เลยแก้โค้ดบริดจ์เอง เซิร์ฟเวอร์ที่เพิ่งเปิดจะขอให้เซิร์ฟเวอร์เก่า "ส่งพอร์ตมา" แล้วเซิร์ฟเวอร์เก่าก็ยอมถอย มันจำลองทดสอบในเครื่องก่อนแล้วจึงนำไปใช้จริง เซิร์ฟเวอร์ใหม่จะขอพอร์ตเฉพาะใน 15 วินาทีแรกหลังเปิด ส่วนเซิร์ฟเวอร์ที่ถอยไปแล้วจะรอเงียบๆ ไม่พยายามแย่งคืน ปกติแล้วหน้าต่างแชตล่าสุดจึงเป็นฝ่ายชนะ
แก้ทั้งไฟล์ที่บิลด์แล้วและซอร์สต้นฉบับ ถึงบิลด์ใหม่ทีหลังการแก้ก็ยังอยู่
แต่ในเซสชันแรกการเชื่อมต่อก็ไม่ติดจนจบ ซีเควนซ์จึงสร้างเป็นไฟล์ XML แล้วนำเข้าด้วยการควบคุมหน้าจอ ตั้งแต่เซสชันถัดไปจึงใช้ MCP ใส่แทร็กคำบรรยายและบันทึกโปรเจกต์ได้

ตอนหน้าจะบันทึกวิธีทำซับไตเติลให้ฟุตเทจยาว 62 ชั่วโมง และสิ่งที่ได้เรียนรู้เรื่องการใช้ AI ทำงานให้มีประสิทธิภาพ
